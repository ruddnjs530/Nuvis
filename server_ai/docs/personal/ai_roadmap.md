# 스마트 홈 로봇 AI 파트 전체 로드맵

이 문서는 프로젝트가 끝날 때까지 AI 담당자가 밟아나갈 전체 개발 여정(Roadmap)입니다.

## 📐 운영 구조 메모
- `server_ai`: 추천 AI + STT 전용 서비스로 운영
- `YOLO` 비전 노드: 현재 프로토타입은 별도 보관 중이나, 최종 모노레포에서는 `ros2_ws` 측 비전 패키지로 재배치 예정
- 즉, AI 기능 중에서도 **API 서비스형 추론**과 **ROS2 런타임형 비전 노드**를 분리해서 관리
- 배포 기준은 **일반 서버(Docker / Jenkins)** 와 **GPU 서버(`server_ai` 단독 운영)** 로 분리하는 방향을 우선 채택

## 🏁 Phase 0: 프로젝트 기획 및 환경 세팅 (현재 완료)
- [x] 요구사항(MVP/API) 분석 및 AI 역할 정의
- [x] 각 기능별(비전, 데이터분석, STT) 아키텍처 및 기술 스택 확정
- [x] 모듈별 단독 테스트가 가능한 마이크로 뼈대 코드(Prototype) 작성 및 가상환경 세팅

---

## 🚀 Phase 1: 비전 객체 인식 연동 (최우선 MVP)
*목표: 주행 파트가 안전하게 주행할 수 있도록 로봇의 "눈" 만들어주기*
*배치 원칙: 최종 구조에서는 `server_ai`가 아니라 `ros2_ws` 측 비전 패키지로 운영*
- [ ] 시뮬레이터 / 실제 카메라 토픽(`image_raw`) 수신 확인
- [ ] `yolo_node.py` 모델 통합 및 테스트 환경 Bounding Box 시각화 성공
- [ ] 탐지된 객체의 종류/거리/위치 정보를 주행 파트 ROS2 노드로 넘겨주기 (메시지 포맷 협의)
- [ ] *(선택/고도화)* 스마트홈 특화 타겟 물건(특정 장애물, 애완동물, 커스텀 가구 등) 인식을 위한 Custom Dataset 기반 모델 파인튜닝(YOLO)

---

## 🧠 Phase 2: IoT 데이터 기반 추천 AI 시스템 구현 (핵심 MVP)
*목표: 수집된 센서 데이터를 바탕으로 스마트 홈 자동화 규칙 추천하기*
*배치 원칙: `server_ai` 독립 서비스에서 백엔드 호출 기반으로 운영*
- [ ] 메인 서버 DB와 AI 전용 서버(`FastAPI`) 간 데이터 통신망 구축
- [ ] 백엔드 환경변수 / HTTP 클라이언트 기준으로 GPU 서버 AI 주소 연동
- [ ] 통계/Rule 기반 모델로 1차 추천 (`api/event/ai-suggestions`) 시스템 납품
- [ ] *(고도화)* Scikit-learn / Prophet 등을 활용한 '머신러닝 기반' 시계열 이상 탐지 또는 스케줄 예측 고도화
- [ ] 로봇 대시보드 화면에 AI 추천 결과가 올바르게 렌더링되는지 엔드투엔드(E2E) 테스트
