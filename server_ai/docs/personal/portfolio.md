# 🏆 포트폴리오 (Portfolio)

**프로젝트 명:** 스마트 홈 로봇 (자율 주행 및 홈 IoT 통합 관제 시스템)
**담당 역할:** AI Engineer & ROS2 Vision Developer

---

## 1. 프로젝트 개요 (Overview)
사용자가 웹 대시보드를 통해 집안의 환경(온도, 습도, 미세먼지)을 실시간으로 모니터링하고, 집안의 IoT 모듈(공기청정, 가습, 제습, 에어컨)을 스마트하게 제어하는 시스템. **AI 파트 전담 개발자**로서 "데이터 분석을 통한 스마트 추천", "자연어 기반 음성 제어" 등 핵심 지능형 기능을 구현했습니다. 특히, **AI 서버 ↔ 백엔드 서버 간 연동 아키텍처를 직접 설계·문서화**하여 원활한 데이터 흐름을 보장했습니다.

또한 모노레포 구조 설계 과정에서, **추천 AI와 STT는 `server_ai` 독립 서비스로 완벽히 분리** 관리하는 구조적인 기틀을 마련했습니다. 여기에 더해, **일반 서버(Docker / Jenkins)와 GPU 서버(`server_ai`)를 분리하는 배포 전략**까지 문서화하여 백엔드 / 인프라 협업 기준을 수립했습니다.

## 2. 주요 구현 기능 및 성과 (Key Achievements)



### 🧠 2.2 사용자 맞춤형 AI 추천 시스템 설계 및 구현 (IoT Data Recommendation)
*   **문제**: 유저가 스마트 홈 이벤트를 일일이 등록하기 번거로우며, "쾌적한 상태"의 기준은 유저마다 다름. 또한 AI 서버와 백엔드 서버 간 효율적인 데이터 연동 아키텍처가 필요함.

*   **해결 — 알고리즘:**
    `Pandas` 및 `Scikit-learn` 기반 데이터 과학 파이프라인 구축. 
    - **컨텍스트 기반 동적 임계값 (Context-Aware):** 유저의 생활 패턴(취침/활동/귀가 등)을 시간대별로 분리 분석하여 상황에 최적화된 임계값 추천 로직 구현. (`main.py`)
    - **머신러닝 행동 예측 (Predictive Modeling):** `RandomForestClassifier`를 도입하여 `[시간, 요일, 온/습도, 미세먼지]` 기반의 기기 작동 확률을 분석합니다. (`ml_model.py`)
    - **GPU 가속 시계열 예측 (Phase 3 Prototype):** PyTorch 기반 **LSTM(Long Short-Term Memory)** 모델을 구축하여 과거 흐름 기반의 연속적 행동 예측 파이프라인을 설계했습니다. (`gpu_lstm_model.py`)

*   **해결 — 아키텍처 & GPU 전략:**
    - AI 서버가 DB에 직접 접근하지 않는 **Stateless API (Data Passing)** 설계.
    - **데이터 푸시형 선제적 알림(Proactive Notification) 아키텍처:** 백엔드가 주기적으로 최신 센서 데이터를 AI 서버에 'Push'하고, AI가 이상치(`anomaly_warnings`)를 감지하면 백엔드가 즉시 사용자에게 푸시 알림을 보내는 **선제적 대응 시스템**을 구현했습니다.
    - **GPU 기반 정밀 추천:** 대용량 시계열 이력 데이터를 GPU로 학습하여 정교한 행동 예측(LSTM)을 수행하는 구조를 확립했습니다. (LLM/Vision 연동은 향후 확장 가능성으로 열어두고 보류)

    AI 서버가 DB에 직접 접근하지 않고, 백엔드 서버가 필요한 데이터를 추출하여 API 페이로드로 전달하는 **Stateless API (Data Passing)** 방식을 직접 설계 및 문서화. 인터페이스 계약(Contract)을 명세화하여 백엔드 팀과 병렬 개발이 가능하도록 주도적인 기술 협의를 진행했습니다.

*   **해결 — DB 설계 기여:**
    백엔드 ERD를 검토하여 AI 패턴 분석에 필수적인 **시계열 이력 테이블 2개** 추가를 직접 설계 및 반영:
    - `ROOM_CONDITIONS_HISTORY`: 센서 값을 덮어쓰지 않고 누적 저장하는 이력 테이블
    - `MODULE_CONTROL_LOGS`: 실제 기기 가동/정지 시각이 기록되는 조작 로그 테이블

*   **성과**:
    - 유저 과거 데이터 기반 5% 안전 마진(Safety Margin) 적용 최적 임계값 계산 → FastAPI 엔드포인트로 백엔드 서버에 제공.
    - 공기청정기/가습기/제습기/에어컨 등 **모든 기기 타입에 동일한 AI 로직 재사용 가능**한 확장성 검증 (ERD의 `VARCHAR` 기반 타입 컬럼 활용).
    - Human-in-the-loop → Full-Automation 두 단계 상용화 로드맵 설계 (MVP 안정화 후 완전 자율 제어로 고도화 가능한 구조).
    - 일반 서버 Docker 배포와 GPU 서버 AI 분리 운영, Jenkins 서버별 배포 흐름까지 포함한 **실서비스 배포 전략** 문서화.

*   **해결 — 서비스 강건성 강화 (`2026-03-13` 추가):**
    Stateless API 아키텍처의 잠재적 취약점을 자가 진단하고 다음 3가지 안전장치를 코드에 직접 적용:

    | 안전장치 | 구현 방식 | 효과 |
    |---|---|---|
    | **페이로드 상한선** | `sensor_data[-MAX_RECORDS:]` (최신 500건만 사용) | 대량 이력 전달 시 메모리/처리속도 저하 방지 |
    | **기기별 독립 타임아웃** | `asyncio.wait_for` + `asyncio.to_thread` (기기당 5초) | 1개 기기 분석 실패가 전체 응답 실패로 전파되는 것 차단 |
    | **Fallback 응답** | 타임아웃/오류 시 기기별 개별 fallback 메시지 반환 | 부분 장애 시에도 정상 분석된 기기 결과는 그대로 제공 |
    | **마이크로서비스 자체 방어(Security)** | `BaseHTTPMiddleware` + `.env` 기반 IP 제어 | 백엔드 코드 수정 없이 **IP Whitelisting(403)**, **용량 10MB 제한(OOM 방어, 413)**, **DDoS/Rate Limiting 방어(429)** 구축 |

    > 두 상수(`MAX_RECORDS`, `ANALYSIS_TIMEOUT`)를 파일 최상단에 분리 선언하여 운영 중 튜닝이 필요할 때 코드 한 줄 수정만으로 조정 가능하도록 설계.

    - 패키지 설치 권한(`sudo`)이 없는 컨테이너 특성상 PM2 같은 외부 도구 도입이 사실상 불가한 점을 파악하고, 순수 쉘 스크립트(`start_all_servers.sh`) 기반 다중 AI 서비스 백그라운드 통합 가동 환경 및 런북(Runbook)을 커스텀하게 설계.
    - **서비스 계층화 및 도메인 기반 리팩토링**: 프로젝트가 커짐에 따라 API 로직, 오프라인 학습 스크립트, 데이터 덤프, 테스트 코드를 `api/`, `scripts/`, `data/`, `tests/` 폴더로 엄격히 분리하여 유지보수성을 극대화하고 배포 이미지 경량화의 초석을 마련함.

### 🎙️ 2.3 스마트홈 도메인 특화 STT 파인튜닝 및 음성 제어 통합 (Fine-tuned STT)
*   **문제**: 일반 Whisper 모델 사용 시 "안방 가습기 켜줘" 같은 특정 도메인 명령어에서 낮은 인식률이나 공백 오류 발생. 또한 600GB에 달하는 거대 데이터셋은 현실적인 학습이 불가능함.
*   **해결 — 데이터 전략**: 
    - **Domain Adaptation 전략**: 전체 데이터를 포기하고 프로젝트 핵심 명령어와 일치하는 **AI Hub 카투홈(Car2Home) 데이터셋 1GB(3,978개)**를 전략적으로 추출.
    - **전처리 파트**: 48kHz WAV를 Whisper 표준인 16kHz로 변환하고 JSON 라벨에서 전사 텍스트를 자동 매핑하는 `preprocess_data.py` 구축.
*   **해결 — 파인튜닝**: 
    - **Whisper-small 파인튜닝**: 파이썬 `datasets` 라이브러리의 데드락 이슈를 해결하기 위해 **PyTorch Custom Dataset** 기반 학습 엔진(`finetune_whisper.py`)을 직접 설계.
    - **트러블슈팅**: CUDA Peer Mapping 자원 고갈 오류를 해결하기 위해 `CUDA_VISIBLE_DEVICES`를 통한 단일 GPU 할당 최적화 적용.
*   **성과**:
    - **정밀도**: **CER(문자 오류율) 1.48%** 달성 (업계 기준 5% 이하 우수).
    - **인식률**: 스마트홈 9개 핵심 명령어 벤치마크 테스트 결과 **9/9 (100%) 합격**.
    - **강인성**: "보일락 켜" 같은 음성 오인식 상황에서도 파서(`stt_parser.py`)가 원래 명령어를 복원해내는 유사도 기반 예외 처리 로직 고도화.
    - **백엔드 연동성 강화**: STT 서버 startup 시 백엔드 방 목록(`GET /api/room/name`)을 캐싱하고, `"거실"` 같은 자연어 방 이름을 최종적으로 `roomId`로 변환하여 반환하는 구조를 구현. 백엔드 API 준비 전에도 시연이 가능하도록 fallback 방 맵과 alias 처리(`안방/침실/내방`)를 함께 설계.
    - **대규모 재학습 운영 확장**: 1GB 실험 성공 이후 20GB급 full raw 데이터셋 전처리 파이프라인을 확장하여 **128,468개 샘플 규모**의 재학습 환경을 GPU 서버에 구축하고, 최종적으로 `v2_full` 학습을 완료함.
    - **최종 시연 기준 성능 확보**: 20GB 재학습 모델의 최종 검증 수치 **`eval_cer 1.02%`, `eval_loss 0.0146`**를 확인했고, 동일 조건 비교 벤치마크에서 **`base 77.8% (7/9)` 대비 `v2_full 100.0% (9/9)`**를 달성하여 시연용 STT 파이프라인을 `v2_full + parser 보정` 조합으로 확정함.
    - **실서버 응답 검증 완료**: GPU 서버에서 실제 `/api/stt/transcribe` 호출 기준으로 `"거실에 가서 공기청소기 켜 줘."`를 `roomId=1`, `module=air_purifier`, `state=on`으로 정상 변환하는 응답까지 확인함.
    - **운영 안정화 적용**: FastAPI `lifespan` 기반 startup 초기화, 임시 파일 충돌 방지, `GET /api/stt/health` 헬스체크 엔드포인트까지 반영하여 시연 전 점검성과 운영 가시성을 높임.

## 4. 팀 회고 및 배운 점 (Retrospective)

- **데이터 효율화 경험 (Domain Adaptation)**: 단순히 거대 데이터를 쏟아붓는 것이 아니라, 프로젝트 목표에 직결되는 고품질 1GB 데이터를 정밀 타격하여 짧은 시간(9분) 내에 압도적 인식률(CER 1.48%)을 뽑아내는 데이터 전략의 중요성을 학습함.

- **AI 라이브러리 제어 및 우회 역량**: 최신 `datasets` 라이브러리의 내부 엔진 충돌(Torchcodec/Deadlock)과 GPU 자원 할당 이슈를 직접 분석하고, PyTorch Low-level API를 활용한 커스텀 데이터셋 구조로 전환하여 문제를 정면 돌파함.

- **STT-Parser 결합을 통한 강인한 시스템 설계**: AI 모델(Whisper)의 한계를 인정하고, 뒷단의 파서(`stt_parser.py`)에서 유사도 기반 키워드 매핑을 적용함으로써 음성 오인식 시에도 시스템은 정상 작동하게 하는 **실패 방지 설계(Fail-safe Design)** 경험 확보.



- **Cold Start 문제 해결 경험**: 프로젝트 초반 실 데이터가 없는 환경을 극복하기 위해 더미 데이터 모의 생성기(`generate_mock_data.py`)를 개발하여 메인 서버 및 알고리즘 검증을 블로킹 없이 병렬로 진행하는 능력을 기름.

- **시스템 설계 및 팀 간 기술 협의 경험**: AI 서버가 DB에 직접 접근하는 방식 대신, 백엔드 서버가 데이터를 추출하여 전달하는 Stateless API 방식의 장단점(응답 속도, 서버 부하 분산, 확장성)을 직접 분석하고 연동 표준으로 제안. 또한 **"AI가 능동적으로 알려줄 것인가(Push), 백엔드가 필요할 때만 물어볼 것인가(Polling)"**에 대한 기술적 논의를 주도하여, 실시간성과 독립성을 모두 챙길 수 있는 **데이터 푸시형 분석 구조**를 확립함. 단순 코딩을 넘어 **서버 간 인터페이스 계약 설계** 역량을 키움.

- **DB 설계 기여 경험**: 단순히 AI 알고리즘 구현에 머무르지 않고, ERD를 직접 분석하여 AI 모델이 필요로 하는 데이터 구조(시계열 이력)가 누락되었음을 능동적으로 파악하고 테이블 설계 및 추가를 직접 반영하는 Cross-functional 경험.

- **인프라 제약 극복 및 MLOps 경험**: 보안 웹 환경(JupyterHub)의 제약을 파악하고 `git sparse-checkout`으로 GPU 서버 배포 전략을 개선함. 나아가 `crontab`과 `sudo` 권한마저 철저히 차단된 닫힌 컨테이너 빌드 환경에서, Bash 무한 루프 데몬 봇과 커스텀 통합 구동 스크립트(`start_all_servers.sh`)를 직접 개발해 '주기적 모델 자동 재학습' 및 '서버 다운 시 원클릭 복구 런북(Runbook)'을 자력으로 뚫어내는 딥러닝/DevOps 트러블슈팅 경험을 축적함.

- **아키텍처 강건성 개선 경험**: 단순 코딩 완성에 머물지 않고, 기존 Stateless API 설계의 잠재적 취약점(페이로드 폭발, 장애 전파)을 스스로 진단하고 `MAX_RECORDS`(페이로드 상한), 기기별 `asyncio` 타임아웃, Fallback 응답 패턴을 코드에 직접 적용. **아키텍처 감사와 지속적 개선** 습관을 키움.

- **서버 간 연동 및 인터페이스 설계 경험**: AI 서버 인터페이스 설계부터 타임아웃 정책, Fallback 처리를 설계하고 백엔드 팀과 조율하는 과정을 통해 **서버 간 통신 설계의 전체 맥락**을 이해함.

- **분리 배포 전략 수립 경험**: "Docker로 통합 배포"와 "GPU 서버 분리 운영"이 충돌하지 않음을 구조적으로 정리하고, Jenkins 기준으로 일반 서버와 GPU 서버를 각기 다른 방식으로 배포할 수 있도록 문서화함. 이를 통해 인프라/백엔드 협업에서 자주 혼동되는 배포 개념과 실행 위치를 명확히 분리하는 경험을 확보함.

- **GPU 기반 AI 서비스 고도화 역량**: 단순 통계를 넘어 **랜덤 포레스트(Random Forest)**와 **LSTM(시계열 딥러닝)** 모델을 설계하고 GPU 가속 환경에 최적화하여 구현함. 특히 복잡한 유저 시나리오를 시계열 윈도우 수치로 변환하여 행동 확률을 예측하는 정교한 분석 파이프라인 구축 경험 확보.

- **마이크로서비스 자체 방어(Self-Protection) 보안 설계 경험**: 메인 백엔드(Spring) 구조를 일절 수정하지 않고도 AI 서버 단독으로 외부 공격 방어막을 구축하는 클라우드 아키텍처(12-Factor App)를 고민했습니다. FastAPI의 `BaseHTTPMiddleware`와 공유 `.env` 환경변수를 결합하여 **인가된 메인 서버 IP만 허용(Whitelisting), 대용량 데이터 전송 차단(OOM 방어), 초과 트래픽 제한(DDoS 방어)** 로직을 동적으로 파이프라인에 주입해 백엔드 의존성이 없는 엔터프라이즈 특화 API 보안망 설계 역량을 입증했습니다.

- **미래의 유지보수 담당자를 배려한 코드 레벨 문서화(Documentation) 습관**: 완성된 로직 기능에 만족하지 않고, 추후에 합류할 팀원이나 코드를 이어받을 담당자가 아키텍처 핵심 설계 의도(왜 `librosa`를 썼는지, 추천 서버의 대량 연산을 왜 비동기 멀티스레드로 뺐는지, 쉘에서 왜 `nohup`을 썼는지 등)를 직관적으로 빠르게 파악할 수 있도록 전체 AI 서비스 소스 코드와 배포 스크립트를 라인 단위로 상세하게 주석 처리하는 탄탄한 협업 마인드를 길렀습니다.
