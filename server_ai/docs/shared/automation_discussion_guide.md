# 🤖 AI 완전 자동화 환경 피드백 연동 방안 (백엔드 팀 논의용)

현재 시스템은 사용자가 앱에서 "AI 추천" 버튼을 명시적으로 눌러야만 추천 기준값(Threshold)을 제공하는 **On-Demand(요청 시 응답) 구조**입니다.

그러나 **시뮬레이터 시연 상황**에서 백엔드가 "미세먼지 200 발사!" 등 하드코딩된 갑작스러운 센서값 변화를 주었을 때, **유저의 클릭 없이도 로봇이 즉각 반응하여 공기청정기를 가동하는 "완전 자동화(Full-Automation)" 시나리오**를 달성하기 위해 아래 두 가지 연동 방식 중 하나를 합의해야 합니다.

---

## 💡 제안 A: 메인 서버가 센서값을 AI로 밀어주기 (Push 방식 / 추천)

**[작동 흐름]**
1. 메인 서버(Spring 등)는 자체 스케줄러를 통해 N초 단위로 방 안의 시뮬레이터 센서 데이터를 갱신(감시)합니다.
2. 메인 서버는 갱신된 최신 데이터(JSON 등)를 AI 서버에 새로 개설된 API(`POST /api/ai/analyze-realtime`)로 N초마다 보냅니다.
3. AI 서버는 데이터를 받자마자 미리 분석해둔 임계값(예: 미세먼지 96.8)과 비교합니다.
4. 만약 임계값을 초과(예: 150)했다면, AI 서버는 즉각 **HTTP 응답(Response 200)**으로 `{"action": "trigger", "robot_command": "move_to_kitchen_and_purify"}` 와 같은 긴급 작동 명령을 메인 서버로 반환합니다.
5. 메인 서버는 이 응답을 받는 즉시 로봇 제어 시스템으로 명령을 전달합니다.

**[장점]**
- 시연 시 **가장 실시간성(Real-time)이 높은 극적인 연출**이 가능합니다.
- 데이터베이스(DB)에 잦은 I/O(조회) 과부하가 걸리지 않습니다.
- AI 서버가 DB 접근 권한을 알 필요 없이 오직 수학적 계산 및 판단만 수행하는 깔끔한 MSA(Micro Service Architecture) 분리가 가능합니다.

---

## 💡 제안 B: AI 서버가 수시로 DB를 감시하기 (Polling 방식)

**[작동 흐름]**
1. 메인 서버는 시뮬레이터 데이터를 받아서 묵묵히 DB의 `sensor_log` 테이블에 저장(Insert/Update)만 합니다.
2. AI 서버(Python/FastAPI) 내부에 **스케줄러 스레드(Background Task)**를 띄워 매 5~10초마다 직접 DB 테이블을 조회(`SELECT`)합니다.
3. 조회 결과, 미세먼지가 비정상 수치(150)임을 AI 서버가 감지합니다.
4. AI 서버가 메인 서버 쪽에 직접 API(`POST /api/server/robot-control`)를 찔러 **로봇 강제 구동 이벤트**를 발생(Triggering)시킵니다.

**[장점]**
- 메인 서버 로직을 수정할 필요가 거의 없습니다. 저장만 잘 해두면 되므로 백엔드 개발자들의 부담이 줄어듭니다.
- 단방향 통신(AI $\rightarrow$ Server)으로 로직 흐름이 단순해집니다.

## 🗣️ 백엔드 팀과 의논할 핵심 질문
> 백엔드 파트 담당자 분들과 회의 시 아래 내용을 바탕으로 하나를 결정해 주시면, 그에 맞춰 AI 서버(FastAPI)의 코드를 즉시 개조하겠습니다.

1. **"저희 시연 때 미세먼지 폭증 이벤트를 AI가 100% 자동으로 잡아서 출동시키려고 하는데, 제안 A처럼 백엔드에서 AI쪽으로 5초마다 데이터를 쏴주시겠어요? 아니면 제안 B처럼 AI에서 직접 DB를 5초마다 긁어갈까요?"**
2. (제안 A 선택 시) **"AI로 보내주실 실시간 센서 데이터 JSON 구조는 어떻게 짤까요?"**
3. (제안 B 선택 시) **"센서 데이터가 기록되는 DB 접속 계정(또는 API) 정보와, AI 측에서 로봇 출동을 명령할 때 찌를 메인 서버 쪽 API 주소는 무엇인가요?"**
