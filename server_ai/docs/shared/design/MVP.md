# 웹 대시보드

| **ID** | **내용** |
| --- | --- |
| FR10 | 사용자는 2D 지도 상에서 로봇의 실시간 위치와 이동 경로를 확인할 수 있어야 한다. |
| FR11 | 사용자는 각 방의 센서 상태(온도, 습도, 미세먼지 등)를 실시간으로 모니터링할 수 있어야 한다. |
| FR12 | 사용자는 특정 시간이나 요일에 로봇이 작동하도록 스케줄(CRUD)을 설정할 수 있어야 한다. |
| FR13 | 사용자는 대시보드에서 로봇을 특정 위치로 수동 이동시키거나 모듈 작동을 제어할 수 있어야 한다. |
| FR14 | 사용자는 로봇에 부착된 카메라가 전송하는 실시간 비전/주행 화면을 대시보드에서 조회할 수 있어야 한다. |
| FR15 | 사용자는 특정 센서 수치 도달 시 발동하는 이벤트(예: 미세먼지 나쁨 시 공기청정)를 생성 및 관리(CRUD)할 수 있어야 한다. |
| FR16 | *(확장)* 사용자는 AI가 사용자 패턴을 기반으로 제안하는 스케줄을 확인하고 적용할 수 있어야 한다. |
| FR17 | *(확장)* 사용자는 STT(음성 인식)를 통해 로봇에게 이동 및 작업 명령을 내릴 수 있어야 한다. |

# 서버

| **ID** | **내용** |
| --- | --- |
| FR20 | 서버는 집안 내 IoT 센서로부터 온도, 습도, 미세먼지 데이터를 주기적으로 수집하는 API를 제공해야 한다. |
| FR21 | 서버는 수집된 데이터를 바탕으로 등록된 이벤트를 판단하고, 조건 충족 시 로봇 베이스에 이동 명령을 하달해야 한다. |
| FR22 | 서버는 작업 스케줄러를 통해 설정된 시각이 되면 해당되는 장소로 로봇 이동 및 모듈 실행 명령을 하달해야 한다. |
| FR23 | 서버는 자율주행 봇 및 상단 모듈에게 정확한 명령(JSON, ROS2 Topic 등)을 전달하고 응답을 수신해야 한다. |
| FR24 | 서버는 로봇의 주행 이력, 모듈 작동 로그, 센서 수치 변화, 에러 내역을 DB에 저장하고 관리해야 한다. |

# 자율주행 봇

| **ID** | **내용** |
| --- | --- |
| FR40 | 봇은 시뮬레이터 환경 내에서 카메라 비전 데이터를 활용해 차선을 인식하고 주행 제어를 수행하여 목적지까지 이동해야 한다. |
| FR41 | 봇은 주행 중 전방 장애물을 인식할 경우 충돌을 피하기 위해 정지하거나 회피 기동을 수행해야 한다. |

| FR43 | 봇은 주행 제어 및 차선 인식에 사용되는 전방 카메라 화면을 대시보드로 스트리밍할 수 있어야 한다. |
| FR44 | 봇은 상단에 장착된 모듈의 하드웨어적 연결을 인식하고, 서버의 제어 명령을 모듈로 토스하는 인터페이스를 제공해야 한다. |
