> **최종 갱신일:** 2026-03-23

> **베이스 모델:** `openai/whisper-small`  
> **비교 대상:** `base` vs `v2_full`  
> **목적:** 시연 기준으로 사용할 STT 파이프라인 확정

---

## 📌 최종 결론

- 시연 기준 최종 선택 모델: `stt/model/v2_full`
- 동일한 테스트셋에서 `base`는 **77.8% (7/9)**, `v2_full`은 **100.0% (9/9)**를 기록
- `v2_full`은 일부 기기명을 오인식했지만, `stt_parser.py`의 도메인 alias 보정과 결합했을 때 최종 파이프라인 정확도가 가장 높았음
- 따라서 운영 기준은 **`v2_full + 보정된 parser + roomId 변환`** 조합으로 확정
- GPU 서버 실서버 API `/api/stt/transcribe` 스모크 테스트에서도 샘플 음성 기준 `roomId=1`, `module=air_purifier`, `state=on` 응답을 확인
- 운영 점검용 `GET /api/stt/health` 엔드포인트를 추가해 모델 경로, GPU 사용 여부, room map source를 실시간으로 확인 가능하게 함

## 4. 특이 케이스 분석

### `base` 취약 케이스
- `제습기`를 `재습기`로 인식해 모듈 파싱 실패
- `안방`을 `앙빵`으로 인식해 room parsing 실패

### `v2_full` 복원 케이스
- `공기청정기 -> 공기청소기 / 공기 천장기 / 공기 천천히`
- `가습기 -> 가스 불 / 가스 기`
- `내방 -> 내 방`
- `켜지마 -> 켜지 마`

위 케이스는 `stt_parser.py`의 alias 보정과 부정어 정규식 확장으로 정상 복원됨.

## 6. 실서버 API 스모크 테스트

### 테스트 환경

- 실행 서버: GPU 서버 `stt/main.py`
- 엔드포인트: `POST /api/stt/transcribe`
- 포트: `9001`
- 검증 클라이언트: `server_ai/test_client.py`
- 사용 오디오: `stt/test_audio/test_00.mp3`

### 응답 결과

| 항목 | 값 |
|---|---|
| STT 인식 결과 | `거실에 가서 공기청소기 켜 줘.` |
| action | `move_and_operate` |
| roomId | `1` |
| module | `air_purifier` |
| state | `on` |

### 해석

- 실제 API 응답 기준으로도 `공기청소기` 오인식을 parser가 정상 복원함
- `roomId` 변환이 응답 JSON에 포함되어 백엔드 계약 방향과 일치함
- 따라서 벤치마크 결과뿐 아니라 실서버 호출 기준으로도 시연 파이프라인이 정상 동작함

## 7. 운영 헬스체크

### 엔드포인트

- `GET /api/stt/health`

### 확인 가능한 항목

| 항목 | 설명 |
|---|---|
| `status` | 서버 기동 상태 |
| `device` | 현재 추론 장치 (`cuda` / `cpu`) |
| `model_path` | 실제 로드된 모델 경로 |
| `room_map_source` | `backend` 또는 `fallback` |
| `room_map_count` | 현재 캐시된 방 이름 수 |
| `room_map_preview` | 현재 room map 미리보기 |

### 2026-03-23 확인 결과

| 항목 | 값 |
|---|---|
| status | `ok` |
| device | `cuda` |
| model_path | `/home/j-j14b110/smart_home_ai/server_ai/stt/model/v2_full` |
| room_map_source | `fallback` |
| room_map_count | `5` |

### 해석

- 현재 백엔드 `GET /api/room/name`이 미연동 상태라 `fallback` 맵으로 동작하는 것이 정상
- 나중에 실제 연동 후에는 `room_map_source`가 `backend`로 바뀌는지만 보면 됨
