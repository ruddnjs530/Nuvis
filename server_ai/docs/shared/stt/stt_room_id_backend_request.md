# STT 방 이름 -> roomId 매핑 연동 요청서

> 작성 대상: 백엔드 담당자
> 작성 목적: AI 서버 STT 결과를 백엔드/프론트엔드의 `roomId` 기준 구조에 맞춰 연동하기 위한 API 계약 요청

## 1. 배경

현재 AI 서버의 STT 파이프라인은 음성 명령을 다음처럼 텍스트 기반으로 해석하고 있습니다.

- 예시 입력: `"거실에 제습기 켜줘"`
- 현재 AI 파싱 결과 예시:

```json
{
  "action": "move_and_operate",
  "target_room": "living_room",
  "module": "dehumidifier",
  "state": "on"
}
```

하지만 백엔드와 프론트엔드에서는 방 식별을 문자열이 아니라 `roomId` 기준으로 사용하고 있어, AI 서버도 최종적으로 `roomId`를 기준으로 응답하도록 맞추려 합니다.

## 2. 목표

AI 서버에서 STT 텍스트를 파싱한 뒤, 방 이름을 내부적으로 `roomId`로 변환해서 백엔드에 전달하고 싶습니다.

예를 들어:

- 음성 입력: `"거실에 제습기 켜줘"`
- AI 서버 최종 응답:

```json
{
  "status": "success",
  "recognized_text": "거실에 제습기 켜줘",
  "robot_command": {
    "action": "move_and_operate",
    "roomId": 1,
    "module": "dehumidifier",
    "state": "on"
  }
}
```

즉, AI 서버 내부에서 `"거실" -> 1` 매핑이 가능해야 합니다.

## 3. 백엔드에 필요한 API

이번 연동은 시연용 기준으로 진행하며, 방 정보는 DB에 고정된 이름으로 들어가 있다고 가정합니다.
AI 서버가 서버 시작 시점에 1회 방 목록을 조회해서 메모리에 캐싱할 수 있도록 아래 API 제공이 필요합니다.

현재 공유 폴더의 API 명세 파일에서는 Room 관련 엔드포인트로 아래 두 개가 확인됩니다.

- `GET /api/room/data`
- `GET /api/room/map`

이번 STT 연동을 위해서는 방 이름과 `roomId`를 조회할 수 있는 엔드포인트가 추가로 필요합니다.

### 요청 엔드포인트

- `GET /api/room/name`

### 기대 응답 형식

```json
[
  { "roomId": 1, "name": "거실" },
  { "roomId": 2, "name": "주방" },
  { "roomId": 3, "name": "안방" }
]
```

### 최소 필요 필드

- `roomId`: 정수형 방 식별자
- `name`: 사용자가 실제로 부르는 방 이름

## 4. AI 서버 적용 방식

AI 서버는 아래 흐름으로 사용할 예정입니다.

1. 서버 시작 시 백엔드의 `GET /api/room/name` 호출
2. 응답을 기반으로 `{ "거실": 1, "주방": 2, "안방": 3 }` 형태의 맵 구성
3. STT 파싱 시 방 이름이 검출되면 해당 `roomId`로 변환
4. 백엔드에는 문자열 방 이름 대신 `roomId` 포함 결과를 전달
5. API 호출 실패 시에는 fallback 하드코딩 맵으로 임시 처리 예정

## 5. 백엔드와 맞춰야 하는 사항

- `GET /api/room/name` 응답은 AI 서버가 바로 사용 가능하도록 `roomId`, `name` 필드를 포함해야 합니다.
- `name` 값은 시연용 DB에 들어갈 고정 방 이름과 동일해야 합니다.
- 예: `거실`, `주방`, `안방`
- AI 서버는 이 값을 기준으로 `{ "거실": 1, "주방": 2, "안방": 3 }` 형태의 맵을 구성할 예정입니다.

## 6. 별칭 처리 관련 메모

AI 서버에서는 사용자가 다음처럼 조금 다르게 말할 수 있습니다.

- `안방`
- `침실`
- `내방`

시연 단계에서는 DB에는 대표 이름만 저장하고, 필요한 별칭 처리는 AI 서버 쪽 파서에서 보완하는 방향으로 진행할 수 있습니다.

예:

- DB 이름: `안방`
- AI 서버 별칭 처리: `침실`, `내방` -> `안방`의 `roomId`

즉, 백엔드에서는 우선 대표 방 이름 기준으로 `GET /api/room/name` 응답만 내려주시면 됩니다.

## 7. 요청 사항 정리

- `GET /api/room/name` 엔드포인트 추가 또는 공유 API 명세 반영 요청
- 응답 형식은 `[{ "roomId": 1, "name": "거실" }]`
- 시연용 DB에 고정 방 이름 저장
- AI 서버가 startup 시점에 1회 조회 후 캐싱할 수 있도록 구성

## 8. 한 줄 요약

시연 단계에서는 DB에 고정된 방 이름을 넣어두고, 백엔드에서 `GET /api/room/name`만 제공해주시면 AI 서버가 방 이름을 `roomId`로 변환해서 사용하겠습니다.
